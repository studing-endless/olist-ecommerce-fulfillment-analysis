# 方法与指标

## 数据粒度与关联

这里的“粒度”指一行数据代表什么。商品或评价表里，一笔订单可能占多行；先整理到订单层面，再计算比例，可以避免同一笔订单被重复计入。

订单表 `olist_orders` 一行一订单；以 `customer_id` 关联客户表，`customer_unique_id` 用于识别跨订单客户及回归聚类。商品明细 `olist_order_items` 通过 `order_id` 先聚合后关联；`seller_id` 关联卖家表。评价表先按订单统计记录数，避免多条评价使同一订单获得更高权重。

支付、商品、地理和品类翻译表在导入范围内；当前回归未使用商品品类、距离或支付方式。不能把潜在可用字段描述为已经使用的控制变量。

## 过滤与时间精度

基础样本要求 `order_status='delivered'`，下单、收货、承诺日期非空，且完整收货时间戳不早于下单。96,478 笔 delivered 记录中 8 笔缺收货时间，最终有效 96,470 笔。

配送耗时 = `(收货时间戳 - 下单时间戳) / 86400秒`；承诺周期 = `DATEDIFF(承诺日, 下单日)`；超期天数 = `DATEDIFF(收货日, 承诺日)`；延迟 = 超期天数 > 0。同日收货不算延迟。

阶段分析另要求下单 ≤ 交承运方 ≤ 收货，得到 96,281 笔。排除的 189 笔对应 1 笔缺交承运方时间、165 笔交承运方早于下单、23 笔交承运方晚于收货。单卖家交运诊断 95,029 笔是另一个子样本。

配送中位数取中间一个或两个观测；P90/P95 使用 nearest-rank：排序后第 `CEIL(n*p)` 个观测。不能用默认线性插值分位数代替。

## 评价分析

主分析保留恰有一条评价记录且评分非空的订单。96,470 笔基础样本中排除 646 笔无评价订单、525 笔多评价订单（其中 189 笔评分冲突），得到 95,299 笔。差评定义评分 ≤ 2，不代表每条评论文字都负面。

分组为超期 ≤0、1—3、4—7、≥8 天。风险差 RD=p_late-p_ontime；RR=p_late/p_ontime。RD 置信区间用 Newcombe 方法，RR 用 log 方法；两者为未调整区间，未按客户聚类。

Logistic GLM：`is_bad_review ~ is_late + C(customer_state) + C(order_month)`，二项分布，标准误按客户唯一 ID 聚类，检查模型收敛，OR=exp(延迟系数)。OR 与 RR 含义不同。P 值打印为 0 是数值下溢，不代表数学上概率为零，因此展示效应量与置信区间。

用通俗的话说，RD看两组差评率相差多少个百分点，RR看两组差评率相差多少倍，OR先分别计算两组的“差评概率/非差评概率”，再比较这两个比值的倍数。三者不能互相替代；置信区间用于说明估计的不确定程度，不代表已经证明因果关系。

多评价敏感性：分别按任意评分≤2、所有评分≤2 两种规则纳入多评价订单；检查结论是否依赖评分归并规则。该检查不能消除评价缺失选择偏差。

## 地区与时期

地区使用客户所在州。时期比较限定 2017-09-01 ≤ 下单时间 < 2018-07-01：前期 9—10 月，高延迟期 2017-11 至 2018-03，后期 2018-04 至 06。时期由观察到的月度变化划分，不是预注册干预实验。

卖家同州/异州依据卖家注册地址与客户所在州，不是仓库坐标或实际物流路线；卖家来源州分析仅保留单卖家订单及有效阶段时间。

## 卖家画像与筛查

本节记录完整历史样本的原筛选规则。按时间切分的策略比较会重新计算截止日前的基准，样本和结果需分别阅读，见[卖家调查策略报告](seller_decision_case.md)。

单卖家订单：`COUNT(DISTINCT seller_id)=1`，用 `MIN(seller_id)` 取得组内唯一卖家。基础样本 95,195 笔、2,948 名卖家，其中 94,051 笔有单条有效评价。延迟率分母是订单数，差评率分母是有效评价订单数。

保留原代码已四舍五入的基准 6.85%、12.33% 及严格大于条件。订单量≥100 且有有效评价的卖家进入四象限，共 201 名。55 名双高候选中，问题订单数=`late_orders+bad_review_orders-late_bad_orders`，问题占比=问题订单数/有效订单数。分别取数量前五与占比前五并集，形成 9 人短名单。

敏感性分析采用 50、100、150 笔门槛，沿用原脚本的未四舍五入问题占比排名；主名单排名使用原脚本保留两位小数的问题占比。未擅自统一两处精度或调整选人规则。

## 交运与金额

交运截止时间来自商品层 `shipping_limit_date`。本地数据核验：95,195 笔单卖家订单内各商品的截止时间一致且无缺失，所以沿用原代码 `MIN(shipping_limit_date)`；其他数据版本必须重新检查。交运超期比较完整时间戳，最终延迟按自然日。两者分母及含义不同。

订单金额为商品明细 `SUM(price+freight_value)`，单位巴西雷亚尔 R$，不是支付表收款核销。问题订单用延迟或单条有效低评分并集确定；无评价订单仍可因延迟进入问题订单。金额按订单聚合并去重，不等同于损失。

## 交付完整性的探索

沿用补充 SQL，仅比较准时且有单条有效评价的订单。商品数是订单明细行数；恰两条明细时比较一名与两名卖家。差评回复时间使用 `review_answer_timestamp`，不能用调查生成时间 `review_creation_date` 替代。少量人工评论阅读未形成带随机种子、样本清单和复核标签的结果，不发布评论原文或总体投诉比例。

## 如何区分策略比较中的比例

问题覆盖率的分母是共同可比较样本中的全部问题订单，衡量名单涉及了多少已观察问题；覆盖订单内的问题率以该名单自己的订单为分母，衡量问题出现得多不多。前者高，可能与订单规模大有关；后者高，也可能只涉及较少订单。两者应同时看，金额则另作交易规模解释。
