# 卖家调查优先级：有限名额下的策略取舍

## 1. 为什么需要比较调查名单

已有分析显示，配送延迟与差评存在关联，也据此形成了一份卖家调查名单。但名单里的卖家表现偏差，并不直接说明这套规则比其他方案更适合分配调查名额。平台资源有限时，还需要比较：同样调查少量卖家，哪种名单涉及的后续问题更多，哪种名单更集中于问题比例较高的卖家。

**本次组合规则没有超过简单数量排序。按历史总订单量排序覆盖的问题数量最多；按历史问题占比排序覆盖的数量较少，但所覆盖订单的问题发生比例更高。** 两种结果对应不同的调查目标，需要分别解读。

## 2. 怎样让四种方案公平比较

- 把 **2018-04-01 00:00** 设为选人时间，所有方案都只能使用记录中此前已发生的结果。时间戳沿用原数据的无时区时间基准，不作时区转换。
- 为减少少量订单造成的比例波动，只比较当时已有至少 **100 笔有效已交付单卖家订单**、且至少有一笔可用单条评分的卖家。订单数和评价数仍分别计算，使用不同分母。
- 历史样本包含 **2,014 名卖家、59,783 笔订单**，其中 **58,298 笔**有当时可用的单条评分。**130 名**卖家符合比较条件，覆盖 **33,495 笔**历史订单，占全部历史有效单卖家订单的 **56.03%**。100 笔门槛下已有足够对象开展比较，无需调整门槛。
- 组合策略A按原规则实际选出 **K=9**，B/C/D也各选 **9 名**，保证调查名额相同。原完整历史分析同样得到9名候选，但两次使用的样本不同，本次名单没有沿用原名单，也没有借助未来订单数补人。
- 比较范围为四种策略，名单在选人时确定，不根据卖家后续是否仍有订单重新筛选。预算按每名卖家占一个名额计算；实际调查所需工时没有记录，因此名额相同不等于实际成本完全相同。

## 3. 四种策略分别关注什么

四种策略都从同一批130名合资格卖家中选择，差别在于各自优先关注的问题。

- **A 组合规则**：先找出延迟率和有效评价差评率均高于按订单汇总的历史整体水平的卖家，再取问题订单数量前5与问题占比前5的并集。本次有35名卖家同时满足两项条件。这一步属于A的筛选规则；四种策略共用的准入条件仍是100笔订单及有可用评价。
- **B 历史问题数量**：按历史去重问题订单数量由多到少选择K名，优先关注已经涉及较多问题订单的卖家。
- **C 历史问题占比**：按历史问题订单数占有效订单数的比例选择K名，优先关注问题在其业务中出现得较频繁的卖家。
- **D 历史总订单量**：按有效订单数量由多到少选择K名，优先覆盖业务规模较大的卖家，作为容易解释的规模基线。

A需要比较的历史整体延迟率为 **6.02%（3,598/59,783）**，历史有效评价差评率为 **12.23%**。这些基准都来自截止日前可观察的样本；全历史的6.85%/12.33%和后续时期的总体水平没有用于本次选人。

问题订单沿用原定义：**配送延迟，或有单条有效低评分（≤2分）**。同一订单同时延迟和差评时只计一次。没有可用评价不能说明客户满意，也不能凭空记为差评；如果已经观察到配送延迟，仍记为问题订单。

## 4. 选人时能知道哪些结果

公平比较还需要处理信息出现的先后顺序：一笔订单即使在此前下单，若收货或评价发生在决策日之后，相关结果就不能提前用于选人。

**历史订单**限定为2018-04-01之前下单、也在此前收货的订单；下单、收货和预计日期有效，收货不早于下单，最终数据中的状态为delivered。商品明细合并到订单后，只保留一个不同卖家的订单，沿用原项目定义。历史下单订单共66,638笔，其中单卖家订单65,269笔，最终有59,783笔满足上述条件。

单卖家历史订单中，有 **3,814笔直到截止日及以后才送达**，这些尚未发生的送达结果没有用于选人。其他未进入样本的订单还包括非delivered状态、日期缺失或异常等情况。它们不能被解释为没有问题的订单。

**评价需要另外检查时间**。调查生成日期`review_creation_date`不等于客户作答时间`review_answer_timestamp`；只有两者都早于观察截止，且回答不早于调查生成和下单、生成日期不早于下单日，才将评分视为当时可用。生成日期只有日粒度，因此与下单日比较。随后再按当时可见的记录判断是否恰有一条非空评分，避免用后来才出现的第二条评价改变过去的选人依据。缺少时间或时间倒置的记录不作为已知评分。

历史下单订单对应的评价中，有4,156条在截止日尚不可用；满足送达条件的历史订单中，有1,485笔没有当时可用的单条评分。评价在最终送达前产生并不自动无效，仍沿用原研究的客户体验定义；缺失和多评价情况另外记录，未观察到低分也不等于已有非差评证据。

**后续表现**使用 **2018-04-01（含）至2018-07-01（不含）** 下单的订单，统一观察到 **2018-09-01（不含）**。这样可以给6月末订单留出约两个月的送达和评价时间。该观察点预先固定，送达及评价仍按相同时间规则处理，100笔门槛、历史基准、名单和K均没有根据后续表现调整。

后续共有19,979笔下单订单，其中19,602笔为单卖家订单；19,296笔已经送达且满足日期要求，其余306笔不进入结果分母。在这19,296笔中，有815笔延迟、2,347笔问题订单。

在130名历史合资格卖家中，122名在后续有有效已交付订单，8名没有；这8名并未因后续没有订单而被提前排除。共同资格池后续下单7,211笔，其中 **7,112笔**符合结果比较条件，99笔未进入分母，可用单条评价覆盖率为 **99.25%**。这部分订单只占全部后续有效单卖家订单的36.86%，所以池内覆盖率不能直接代表全平台覆盖率。四种策略最终选中的卖家，在后续均有订单，各为9名。

**这仍是一项历史回顾**。分析按记录中的送达和评价时间限制信息使用，但数据没有保留订单状态、商品卖家归属、金额、评分或预计日期的修改记录。历史中就有 **6笔已经记录送达、最终状态却不是delivered** 的单卖家订单，按原口径排除后，仍无法还原它们在决策日的状态。

因此，结果应理解为**事件时间约束的回顾性时间外比较**，**不能视为已保证所有字段在当时可得的前瞻预测验证，不作预测性优劣结论**。分析还需要假设订单项在下单时已知且此后没有修订、回答时间能够代表评分可用时间；现有数据无法完全核实这些假设。

## 5. 后续订单中的实际表现

四种方案各选出9名待调查卖家，未实际开展调查。表中覆盖率回答的是：这些名单涉及的问题，占共同可比较样本的多少？分母分别为 **7,112笔有效订单、260笔延迟订单、856笔问题订单**，问题订单涉及金额共 **R$136,183.86**。而“问题率”只看各份名单自己覆盖的订单，用来说明其中出现问题的比例。

四份名单在历史中的订单规模原本就不同：A为4,926笔、B为8,430笔、C为2,123笔、D为8,721笔。D/B后续覆盖较多问题订单，与其覆盖较多业务有关；这个结果本身不能证明它们更擅长识别高风险卖家。

覆盖率还取决于比较范围。若以全部后续有效单卖家订单中的2,347笔问题订单为分母，A/B/C/D分别覆盖 **6.69% / 9.46% / 4.99% / 9.97%**，低于共同资格池内的覆盖率。

## 6. 不同目标下如何选择

- **关注问题数量时**，本次D覆盖234笔、B覆盖222笔，都超过A的157笔；D也覆盖了最多订单和延迟订单。D值得作为数量覆盖目标下的简单参照，但一个时期的结果还不能证明它在未来最优。
- **关注问题比例时**，C覆盖订单的问题率为16.23%，高于A/B/D的12.67%/13.03%/12.96%，但只涉及117笔问题订单。它更接近比例异常的专项调查目标，代价是数量覆盖较少，也更需要注意较小规模样本的比例波动。
- **原组合规则没有胜出**。A同时考虑两项指标偏高、问题数量和问题占比，却没有在本次覆盖数量、问题率或涉及金额上形成优势。这说明筛选规则更复杂，并不自然带来更好的调查结果，仍需根据调查目标和其他时期的表现判断是否采用。
- **涉及金额提供了另一个规模视角**：D为R$32,340.36，B为R$30,579.66；C的问题数更少，但涉及金额R$22,987.97仍高于A的R$21,179.29。这里加总的是商品价格和运费，不能解释为损失、可挽回收益、真实收款或调查回报。

## 7. 调查还应检查哪些环节

名单用于决定先检查谁，交运和评价记录则帮助明确检查什么。以下数据都来自后续订单，只用于**事后解释**，没有参与4月1日选人，不能当作决策时已经知道的信息。

- **规模较大的名单**可继续检查后续配送。D的71笔最终延迟订单中，有59笔在有效交运样本中已按时交运（83.10%），因此需要查看运输轨迹、目的地和承诺日期；仅要求卖家加快发货，未必对准这些订单需要核查的环节。
- **问题比例较高的名单**也要区分环节。C的719笔有效交运订单中，84笔交运超期（11.68%）；25笔最终延迟订单中，12笔按时交运、13笔交运已经超期。两类环节都有核查必要，不能直接据此认定责任。
- **准时订单的差评**需要另查原因。C的105笔差评中，92笔发生于最终准时订单；D的199笔差评中，163笔发生于准时订单。商品完整性、商品信息和售后记录都值得补查，但本实验没有为此重新开展文本分析或回归，也未确认具体差评原因。

调查安排应先明确希望涉及更多问题订单，还是优先核查问题比例突出的卖家，再选择相应清单。本案例没有实施整改，历史上覆盖的问题数量也不能被理解为能够避免的问题数量。

## 8. 结果的边界与复现说明

- 比较只有一个决策点和一个季度，缺少置信区间及多期稳定性证据。也没有实际调查成本、干预或对照组，不能证明因果效果和经济收益。
- 结果只覆盖已观察到的有效已交付订单，不能代表未完成或异常状态订单的全部风险；有评价和没有评价的订单也可能存在差异。截止日尚未送达的3,814笔单卖家订单未用于建立历史画像，可能使画像更偏向较早完成配送的订单。
- 100笔门槛有助于减少小样本波动，同时会遗漏新卖家和小卖家。这个门槛没有按后续结果挑选，也没有被证明是最优门槛。
- 若要判断未来是否仍适用，需要先保存决策当日可用的数据版本和名单，再在多个未来窗口比较覆盖情况、单位调查工时，以及有对照的试点效果。这些是后续验证建议，不是已经完成的成果。

此前策略比较升级仅新增卖家策略实验，没有重跑原地区EDA或差评回归；原完整历史的9名候选、原统计结论和5张图保留。原`docs/release_manifest.md`对应首次45文件版本，该次增量由相应分支的Git差异及本报告说明。

在仓库根目录准备本地原始CSV后运行（CSV目录自行设置，不写入仓库）：

```powershell
$env:OLIST_RAW_DIR = '自行下载的CSV目录'
python python/08_seller_strategy_comparison.py
python -m unittest discover -s tests -p 'test_seller_strategy_comparison.py' -v
```

也可用`--raw-dir`、`--output-dir`和`--figure`指定本地输入及输出。脚本只读取订单、商品明细及评价三张表的必要字段；不读取评论原文，不保存卖家名单或ID映射。默认写出三份匿名汇总CSV和一张图，不覆盖旧分析结果。新增的五项测试检查时间边界、未来第二条评价、未来结果扰动、问题并集与共同预算；真实数据另通过截断不变性及分币金额/并集核对。
